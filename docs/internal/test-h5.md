## 测试部署隔离

使用独立 HTTPS 域名、部署目录、端口、服务进程、配对数据库、推送数据库及 VAPID 密钥。不要复用生产数据库、密钥或配对凭证；测试助手在测试域名重新登记和配对。不同域名也会隔离浏览器 cookie、PWA、Service Worker 和推送权限。

relay 从部署目录的 `public/` 读取 HTML、CSS 和 manifest。以下脚本生成测试覆盖文件，给网页标题、侧栏品牌、设备栏和主屏幕名称增加测试标识，不改变生产默认页面：

```sh
node scripts/prepare-test-h5.mjs --output /tmp/codex-test-h5 --origin https://test.example.com
```

将生成的 `desktop.html`、`desktop.css`、`manifest.webmanifest` 仅复制到独立测试部署的 `public/`，再启动测试 relay。每次更新部署代码后重新生成；回滚时恢复测试部署原始文件。脚本拒绝生产域名 `codex.air-inc.top` 及当前源码目录内的输出路径，外部 CSS 符合 relay 的 CSP。

测试环境配置示例：

```text
HUB_ORIGIN=https://test.example.com
PORT=8789
HUB_DATABASE=/srv/codex-phone-test/data/relay.sqlite
HUB_PUSH_DATABASE=/srv/codex-phone-test/data/push.sqlite
HUB_NOTIFICATIONS=1
HUB_PUSH_SUBJECT=mailto:your-test-contact@example.com
HUB_PUSH_PUBLIC_KEY=<测试环境单独生成的公钥>
HUB_PUSH_PRIVATE_KEY=<测试环境单独生成的私钥>
```

反向代理仅将测试域名转发到测试端口。可信本机代理按现有部署要求设置 `HUB_TRUSTED_PROXY=1` 和真实客户端 IP。可用以下命令单独生成测试 VAPID 密钥，保存到仅测试服务可读的环境文件，不写入文档或仓库：

```sh
node --input-type=module -e "import {generateVapidKeys} from './src/notifications/push-service.mjs'; console.log(await generateVapidKeys())"
```

启动后核对网页及 manifest 测试标识。iPhone 从测试域名单独添加到主屏幕，名称应为“手机助手测试版”，再手动开启通知。iPhone 关闭测试版后的待回答及完成系统通知已有用户确认；划掉后台后的角标投递尚未单独确认，真实命令审批仍只有协议与自动化覆盖。双向归档仍延期。验证时保留当前配对隔离。
