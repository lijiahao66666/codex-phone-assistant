## 附件上传

用户真实 iPhone 先复现“传输 413”。线上 Nginx 的站点上限为 `client_max_body_size 64k`，而 H5 每片为 131072 字节。修复仅为上传分片路径增加 `client_max_body_size 128k`，沿用原代理设置；其他路径仍为 64 KB。配置语法校验及热重载通过。公网无凭据边界测试：131072 字节到达应用鉴权并返回 401，131073 字节仍由 Nginx 返回 413。未传递真实附件内容。

服务端配置备份保存在 `/root/codex-nginx-before-upload-20261106-200720.conf`。上传分片使用以下 location：

```nginx
location ~ "^/api/threads/[0-9a-fA-F-]{36}/uploads/[0-9a-fA-F-]{36}/chunks/[0-9]+$" {
    client_max_body_size 128k;
    # 复制当前站点 location / 中的 proxy_pass、代理头和流设置。
}
```

修复 413 后用户复现等待很久再出现“传输 503”。当前运行模块从初始化开始固定 30 秒过期，不随接收分片刷新。真实公网、现用电脑助手和临时测试配对复现：1 MB 文件，每个分片间隔 4.5 秒，前 6 片成功，第 7 片超过总时限后返回 503 unavailable。该测试只暂存文件，不发送消息；临时配对已撤销。

`ChunkUploads` 改为每次成功接收分片刷新 30 秒空闲计时，保留 120 秒总上限。完成、取消和关闭清除两个计时器，取消后的迟到写入不能恢复上传。5 项真实 `UploadStore` 定向测试通过。

根据现用 Mac 助手副本制作 `Codex 手机助手-上传修复-1106.app`，运行模块仅 `chunk-upload.mjs` 不同；ad-hoc 签名验证通过。原预览修复助手退出后启动上传修复版，未修改配对凭据或重启 Codex。相同慢速公网测试中全部 8 片和 finish 成功，文件字节仍为原始内容，临时文件及配对清理成功。快速 1 MB 和 20 MB 暂存测试此前也成功。

H5 临时诊断提示增加了初始化、传输或完成阶段及 HTTP 状态。当次线上 JS SHA-256 为 `e284dfe986d1ff103010e791c44970f391822d8d94a8b1b0838b5b3ab0421aa1`，只包含此诊断。iPhone 完整上传并发送仍在等待实际结果，不能把暂存成功称为发送成功。
