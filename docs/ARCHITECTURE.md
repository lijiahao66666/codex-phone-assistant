# 架构

## 数据流

```text
手机 H5
  │ HTTPS / WebSocket
  ▼
远程中转服务
  │ WSS /connector
  ▼
桌面后台进程（src/runtime.mjs）
  ├─ 配对与本机面板（src/pairing）
  ├─ WebSocket 传输与流控（src/transport）
  ├─ 任务和历史投影（src/desktop）
  └─ 媒体与上传（src/media）
          │
          ▼
Codex Desktop 本地 IPC / 手机助手 app-server
```

## 模块

| 目录 | 职责 |
| --- | --- |
| `src/common` | 跨平台绝对路径、目录边界和键值比较 |
| `src/desktop` | IPC 协议、会话恢复、任务索引、历史分页和状态投影 |
| `src/pairing` | 主机注册、配对码、设备管理、本机管理面板和凭据保护 |
| `src/transport` | WebSocket 连接、消息调度、流控和快照分块 |
| `src/media` | 媒体引用解析、内容校验、分块上传和临时文件 |
| `public` | 本机配对面板及远程 H5 的静态资源 |
| `macos` | Swift 窗口、菜单栏、WKWebView 和媒体辅助程序 |
| `windows` | WinForms、WebView2、托盘行为和安装器 |

## 连接流程

1. 桌面端启动 `src/runtime.mjs`，读取或创建配对凭据。
2. 桌面端连接 `HUB_ORIGIN/connector`，手机访问同一 H5 服务。
3. 手机输入配对码或扫码；桌面端显示确认请求。
4. 配对成功后，手机请求任务列表，桌面端读取 Codex 本地索引和历史。
5. 已由桌面持有的聊天，通过本地 IPC 转发。新聊天和用户确认恢复的无 owner 聊天，由手机助手的 app-server 持有，并向桌面广播。每次写入重新校验归属；发生冲突、进程退出或未知结果时停止后续写入。
6. 状态变化通过订阅推送；断线或版本不连续会清空缓存并重新同步。

## 关键约束

- 写入操作必须携带当前 owner 和任务版本，不使用缓存状态直接执行。
- 历史读取必须限制在 Codex sessions 目录内。
- 手机端不能指定任意本地 socket、HTTP 地址或文件路径。
- 新聊天、恢复和模型切换由 journal 绑定请求、设备和任务；只读历史游标不能授权写入。
- 本机管理面板只监听 loopback，不代理给远程设备。

## 不代理的 Codex 设置

当前协议没有为以下桌面端设置提供安全稳定的控制方法，因此手机端不展示选择入口：

- 新建项目、聊天重命名与归档等管理
- 目标的创建、编辑、暂停、恢复和清除
- 插件、Apps、MCP 和连接器选择
- 执行环境选择
- cwd、Git 分支和 worktree 选择

`Plan`/`Default` 协作模式是独立能力，允许在任务空闲时切换。目标状态只做只读投影。

## 新聊天、模型与附件

新聊天第一次发送才创建。创建 journal 绑定项目、请求标识和内容摘要。带附件时先准备聊天并上传，再提交首条消息。重试沿用同一请求，结果未知时先查询状态，避免重复创建或发送。模型列表从本机 app-server 读取。切换使用独立 journal 和确认状态，与待发送消息互斥。

上传能力按当前 host 连接协商。旧连接器使用 128 KiB 串行分片，新连接器使用 512 KiB 和两片并发。压缩仅用于无损传输，未获收益时传原始字节；按序写盘并确认后才能完成。中转临时转发附件，最终文件暂存于电脑的 `~/.codex/phone-uploads`。

## 历史与控制隔离

实时 IPC 状态提供 owner、运行中任务和待回复请求；已保存历史只用于展示。较早内容的分页游标绑定聊天和设备，不能用只读页的状态执行写操作。任务切换、设备切换、断连和版本变化分别清理对应请求；历史片段合并不改变控制状态。
