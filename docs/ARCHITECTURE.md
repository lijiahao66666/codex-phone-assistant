# 架构

## 数据流

```text
手机 H5
  │ HTTPS / WebSocket
  ▼
远程中转服务
  │ WSS /connector
  ▼
桌面后台进程（src/runtime.mjs）
  ├─ 配对与本机面板（src/pairing）
  ├─ WebSocket 传输与流控（src/transport）
  ├─ 任务和历史投影（src/desktop）
  └─ 媒体与上传（src/media）
          │
          ▼
Codex Desktop 本地 IPC / 手机助手 app-server
```

## 模块

| 目录 | 职责 |
| --- | --- |
| `src/common` | 跨平台绝对路径、目录边界和键值比较 |
| `src/desktop` | IPC 协议、会话恢复、任务索引、历史分页和状态投影 |
| `src/pairing` | 主机注册、配对码、设备管理、本机管理面板和凭据保护 |
| `src/transport` | WebSocket 连接、消息调度、流控和快照分块 |
| `src/media` | 媒体引用解析、内容校验、分块上传和临时文件 |
| `public` | 本机配对面板及远程 H5 的静态资源 |
| `macos` | Swift 窗口、菜单栏、WKWebView 和媒体辅助程序 |
| `windows` | WinForms、WebView2、托盘行为和安装器 |

## 连接流程

1. 桌面端启动 `src/runtime.mjs`，读取或创建配对凭据。
2. 桌面端连接 `HUB_ORIGIN/connector`，手机访问同一 H5 服务。
3. 手机输入配对码或扫码；桌面端显示确认请求。
4. 配对成功后，手机请求任务列表，桌面端读取 Codex 本地索引和历史。
5. 已由桌面持有的聊天，通过本地 IPC 转发。生产环境的新聊天先由手机助手创建和持久化，再释放 writer 并打开 Codex Desktop 对应聊天。确认原生桌面 owner 后才转发首条消息。历史聊天也通过原生桌面恢复，已有可响应的桌面 owner 时直接跟随。每次写入重新校验归属；发生冲突、进程退出或未知结果时停止后续写入。
6. 状态变化通过订阅推送；断线或版本不连续会清空缓存并重新同步。

## 关键约束

- 写入操作必须携带当前 owner 和任务版本，不使用缓存状态直接执行。
- 历史读取必须限制在 Codex sessions 目录内。
- 手机端不能指定任意本地 socket、HTTP 地址或文件路径。
- 新聊天、恢复和模型切换由 journal 绑定请求、设备和任务；只读历史游标不能授权写入。
- 本机管理面板只监听 loopback，不代理给远程设备。

## 不代理的 Codex 设置

当前协议没有为以下桌面端设置提供安全稳定的控制方法，因此手机端不展示选择入口：

- 新建项目、聊天重命名、置顶与移动等管理
- 目标的创建、编辑、暂停、恢复和清除
- 插件、Apps、MCP 和连接器选择
- 执行环境选择
- cwd、Git 分支和 worktree 选择

`Plan`/`Default` 协作模式是独立能力，允许在任务空闲时切换。目标状态只做只读投影。

## 新聊天、模型与附件

新聊天第一次发送才创建。创建 journal 绑定项目、请求标识和内容摘要。带附件时先准备聊天并上传，再提交首条消息。重试沿用同一请求，结果未知时先查询状态，避免重复创建或发送。模型列表从本机 app-server 读取。切换使用独立 journal 和确认状态，与待发送消息互斥。

生产环境在准备阶段设置空聊天名称以持久化，再通过 `codex://threads/<id>` 打开原生桌面聊天并确认其 owner。该过程会切换 Codex Desktop 显示的聊天；H5 可以保持打开。首条消息只经确认后的桌面 owner 发送，交接失败不会改由手机助手执行。自定义 IPC 测试环境可注入打开方式；未配置原生打开方式时保留隔离测试路径。

手机助手创建或恢复线程时设置 `thread_unload_delay_secs: 0`。释放时关闭该线程的新操作入口，等待 unsubscribe 回执。`unsubscribed` 和 `notSubscribed` 还须收到 `thread/closed`；`notLoaded` 则直接确认未加载。确认后移除本地 owner，不发送清空聊天的快照。未知结果保持门禁关闭。

上传能力按当前 host 连接协商。旧连接器使用 128 KiB 串行分片，新连接器使用 512 KiB 和两片并发。压缩仅用于无损传输，未获收益时传原始字节；按序写盘并确认后才能完成。中转临时转发附件，最终文件暂存于电脑的 `~/.codex/phone-uploads`。

## 历史与控制隔离

实时 IPC 状态提供 owner、运行中任务和待回复请求；已保存历史只用于展示。会话订阅建立后并行加载最近历史，不等待 owner 查询结束。实时状态优先，取消、撤销或旧订阅的迟到历史会被丢弃。较早内容的分页游标绑定聊天和设备，不能用只读页的状态执行写操作。任务切换、设备切换、断连和版本变化分别清理对应请求；历史片段合并不改变控制状态。

生产环境的历史恢复复用原生桌面打开流程。先进行有界只读探测，再按需打开 `codex://threads/<id>` 并确认原生 owner 和响应。探测超时不会改由助手竞争 writer，恢复过程也不修改标题或发送消息。原先由助手持有的线程只在空闲和释放确认后交接，忙碌任务仍跟随原 owner。未配置原生打开方式的隔离测试环境保留原 app-server 恢复路径及 journal 保护。

手机页面订阅与任务列表订阅分别标记。原生桌面 owner 不受手机助手的空闲释放策略影响。仍由助手持有的线程在最后一个手机页面离开后，可在安全检查和宽限期后释放；有运行任务、活动目标、排队输入或待处理请求时不释放。
